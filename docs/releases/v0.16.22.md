# v0.16.22 — Timed operation observation

## Changes

- Recognize the literal POSIX `TIMEFORMAT='<ASCII_IDENTIFIER>=%R'; time <command>` envelope when reconciling a native operation, without accepting a different command, output redirection, working directory or arbitrary shell wrapper.
- Retain an already collected operation observation across a unique equivalent declaration in the same working directory. Original ownership, terminal and exit remain attached to the observation; a bare Node declaration cannot prove that a different pinned binary ran.
- Classify `NO_START` and structured failure output separately from the recognized envelope's trailing duration, without changing the native output or exit.
- The change does not import an uncollected call from another owner or run, and does not establish recovery of the original live operation. The regression tests cover the V2 history projection and public Mission APIs, not a replay of that operation.

## Release identity and validation

The intended runtime asset marker is `0.16.22-operation-elapsed-v1`. Record the integrated `main` commit and SHA-256-pinned archive with the candidate preflight, full validation, Linux/Windows CI and actual CLI Worker startup separately; a startup is not completion or an official score. Use the same fixed archive for installation and publication. An installed marker does not prove that an already-running OpenCode host reloaded the plugin; verify the loaded path and marker after a manual restart.
