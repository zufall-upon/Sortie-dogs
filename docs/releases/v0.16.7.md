# v0.16.7 — Release cancelled direct writers from native terminal records

## Fix

A cancelled direct Coordinator could retain its write authorization when a tool's `execute.after` hook was missed. Cancellation had already stopped the owned child and settled its reservation, but `releaseDirectUnit` returned `tools-in-flight`. A replacement Mission then encountered `mission-scope-update-writer-conflict`; redispatching the old Coordinator correctly failed ownership authorization and could not repair it.

Direct release now reuses the existing exact-call native-history reconciliation. Each pending call must have one completed/error tool record in that actor's history; foreign, duplicate, missing, running/pending or background-unknown records retain the writer. Calls admitted while history is loading are not erased by a blanket clear.

If release still cannot complete, its exact authorization identity is retained in memory. The next ordinary bind/scope-expansion operation under the same root retries that requested release before checking overlap. Changed authorizations are not released. No old-Coordinator redispatch, new watcher, user approval, persistent-state migration, raw ledger mutation, budget reset or forced eviction is introduced. A pending cancellation still reports its actual release failure; a later native terminal can resolve the writer without another model dispatch.

## Regression and boundaries

- Public plugin-hook fixtures reproduce missing `execute.after`, stale question activity, delayed terminal, background unknown, missing/duplicate/foreign tool records and repeated/concurrent scope operations.
- The replacement scope succeeds only after native termination is established. Old-Coordinator redispatch stays denied; cancelled reservations are not settled twice and only the replacement direct unit holds new budget.
- Source investigation used saved V2 history read-only. The original product Mission, private artifacts and cumulative spend were not modified or resumed; fixing the harness is not proof of that product's completion.
- Actual ChatGPT browser consultation recommended lazy recovery using the existing native-terminal verifier rather than a new monitor. Consultation is advice, not independent source review or formal PASS.
