# v0.16.9 — Keep one-shot terminal instructions out of active Missions

## Fix

An Advisor admission could arm the shared core's one-shot terminal instruction before any implementation unit or Worker existed. Forwarding that instruction during an active Mission contradicted its retained multi-step requirements and formal acceptance lifecycle.

The profiled system transform now removes only its generated `SORTIE_FAST_LANE_TERMINAL` block while the durable Mission is neither completed nor cancelled, including a stale supplied copy. The existing V2 live-state mechanism withdraws a previously sent block. Genuine one-shot mode remains available outside the active Mission; its default is explicitly not evidence that the user requested a one-unit limit.

No execution/consultation budget, Worker limit, acceptance/validation, compaction capability, parent/child rule or dispatch permission changes. No extra approval, new monitor, schema migration or configuration option. Actual stops must still be judged from the original user request, current host state and native results rather than an assumed user restriction.
