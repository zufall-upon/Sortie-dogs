# v0.16.25 — Execution and validation recovery

## Changes

- Recover eligible predecessor execution evidence and reconcile native terminal state, validation binding and writer ownership without forcibly releasing a live or unknown owner.
- Keep validation scratch exclusions tied to the individual check and preserve declared and Location-tracked inputs. A cwd-relative scratch exclusion not present in the earlier Location-relative recipe is deferred, so generated files in such a nested checkout may make a check stale.
- Recognize quoted Git identity values without weakening command-boundary checks.
- Default the Mission Coordinator to Terra while retaining explicit model overrides and existing role configuration.
- Keep the normal return report concise while retaining its summary, cost and history caveats, and internal records.

The historical stale-evidence record did not retain a per-file snapshot diff, so its unique cause is not established. Execution recovery does not establish completion or official grading of an external task.

## Deferred Git behavior

This candidate retains the published Location-only snapshot Git scan rather than the new nested-checkout scan, and does not include the later recursive submodule Review implementation. The earlier Review path for ordinary nested Git checkouts remains. A synthetic run with a writable nested checkout and its `.git` redirected to another host-readable repository produced that repository's tracked content in `missionReviewSource`'s excerpt in v0.16.24. Actual host permission bypass, real secret disclosure and external transmission were not established by that internal-function reproduction. The collection behavior and broader Git-boundary work remain for follow-up; this is not a claim that the behavior is safe.
