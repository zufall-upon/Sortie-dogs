# v0.16.13 — Git index checks follow native workdir

## Changes

- Inspect the repository actually selected by native shell Location/workdir before a Git commit, including authorized external clones and subdirectory execution. Inspect the whole index with `--no-relative`; preflight never stages, unstages or commits files.
- Include preceding explicit `git add` paths in the prospective index. Preserve scope and explicit caller prohibitions, including when the Mission project and native Location differ. Command-local directory/index overrides and unsupported Git mutation forms retain their existing refusal behavior.
- Reconcile Git's physical repository paths with symlinked workspace and external-clone spellings. Resolve workspace-root aliases while preserving index-relative pathname components; retain physical and authorized alias paths for caller checks.
- Authorize staged symbolic links as directory entries, including dangling links. Entry authorization does not grant writes through their targets. Existing ordinary file-write checks remain in force.
- Preserve missing directory scope components and compare indexed paths independently of current working-tree directory symlinks. Neither a missing directory nor a replaced ancestor can authorize unrelated staged entries.
