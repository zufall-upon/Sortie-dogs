# v0.16.16 — Grip decision holds and native consultation

## Changes

- Add Grip to an active V2 Mission's existing single-choice native question explicitly marked `header: "Grip"`, issued by its Operator or Coordinator. Retain a labelled excerpt of the original user request and a permanent outside-consultation choice. Ordinary questions, input collection, permissions and non-controller sessions are unchanged; unmarked direction questions can still be missed.
- Persist the exact native offer and held direction in the existing Mission state. Consultation pauses new direction-changing planning, implementation, Review and acceptance, plus controller writes and authoring shell. Reads, status, consultation, cancellation and existing Workers' execution, cleanup and settlement remain available.
- Resume only from a fresh corresponding revised Grip question's listed normal choice. Retain free-form steering without silently treating it, stale calls, dismissals, quoted output or external advice as execution permission. Save failures and unavailable native history retain the hold without disabling observation.
- Serialize both initial and revised form admission, reject reused native identities with changed forms, and bind answers/recovery to the same live Mission. No additional approval ritual, GUI, automatic external transmission, Worker kill or budget/permission bypass.

## Review and verification

PR #352's four existing findings were reproduced and corrected: changed-form identity reuse, observation during recovery outages, concurrent initial offers and concurrent revised offers. Related initialization/Grip/V2 selection passed 143 tests; the final development commit passed 2,620 tests with 4 skipped, and Linux/Windows CI succeeded. These are development results, not relabelled as fixed-release validation.

The real OpenCode V2 2.2.2 native Form rendered and accepted the augmented choices in a zero-inference probe. Its blank-line display normalization is accepted. Pinned-source and adapter checks cover inner Code Mode hooks; neither probe claims model E2E, full native QuestionTool-executor coverage, instruction adherence or performance improvement. See [Grip scope and verification boundaries](../grip.md).

Fix one integrated `main` commit and one archive/SHA-256 before candidate preflight, full validation and actual Worker/model startup. Apply that same archive to both global CLI prefixes and OpenCode's config-local package, publish it to GitHub Release and npm once, and preserve model overrides and unrelated settings. Release receipts, costs, archive identity and cleanup observations are retained under `_testenv/releases/0.16.16/`. A Worker-startup fixture does not establish real-development completion or official benchmark scoring.
