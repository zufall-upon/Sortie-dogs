# v0.16.24 — Prelaunch scope recovery

## Changes

- Recover an operation rejected before launch after an effective scope correction, while recording call-, run- and input-bound host receipts and preventing duplicate admission.
- Reconcile native history, including concurrent status reads, unavailable history and contradictory process evidence, without treating a tool envelope or error text as proof that a process started or did not start.
- Resolve a limited initial prefix of immutable PowerShell path definitions without evaluating expressions. Preserve literal-dollar paths and reject unresolved destinations after pipelines, executable prefixes or engine-owned variable assignments.
- Bind the isolated prelaunch-recovery CLI scenario to its actual direct root executor and model; a Worker dispatch is not accepted as that scenario's direct execution.

These changes do not recover another owner's live operation or establish completion or grading of an external task.

## Release identity and validation

The intended runtime asset marker is `0.16.24-prelaunch-scope-recovery-v1`. Record the integrated `main` commit and SHA-256-pinned archive alongside candidate preflight, full validation, Linux/Windows CI, independent review, and actual CLI Worker startup. Startup is not task completion or an official score. Install and publish the same fixed archive. An installed marker does not prove that a running OpenCode host has reloaded the plugin; verify its loaded path and marker after a manual restart.
