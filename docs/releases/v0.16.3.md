# v0.16.3 — Retained-owner strategy and cancelled Task recovery

## Included changes

- Integrates PR #322. Operator compares the original goal, actual result and concrete unmet work when a selected method stalls or unnecessary work is proposed. Concrete alternatives and retained obligations can reach the same ended, quiescent Coordinator through the existing continuation route. A proposal does not admit a new contract, add a reservation, settle work or stop an owner. Planned useful work needs no new approval or logging-only step.
- Integrates PR #323. A Task cancelled before its child's first prompt no longer remains permanently unplannable solely because its saved child is null. Existing native terminal/input/owner/run/call checks and quiescent lineage must establish the exact cancelled calls before planning can continue. Old-generation Task references remain historical comparisons, not renewed admission authority.
- Same-request continuation, unrelated known root children, fresh stop acknowledgements and cancelled-run archiving are covered. Preserve original cancellation/null-child state, prior evidence, nonzero known costs and unknown usage; do not fabricate a terminal, reset budgets or settle twice. Live/unproven owners, pending Review, active tools, freshness, formal validation and final acceptance remain authoritative.
