# v0.16.27 — Git review boundaries

## Changes in the preparation candidate

- Mission Review and delivery observations use a private Git index for worktree comparisons, suppress clean and process filters and fsmonitor hooks in those comparisons, preserve non-filter attributes, and avoid lazy fetching missing objects. Recursive submodule inspection checks metadata before following it and retains the configured submodule ignore behavior.
- Review and snapshot inventory check nested Git metadata before using it, including standalone nested repositories and linked worktrees. Snapshot capture and refresh conservatively protect potential inputs when a Git inventory fails, while the public inventory retains its declared-path fallback.
- A direct POSIX `GIT_INDEX_FILE=<absolute path> git add -- <paths>` can use a scoped alternate index when both the index and explicit operands are authorized. Unresolved POSIX path expansion and double-quoted backtick substitution in Git commit messages are rejected at the write gate.
- Snapshot inventory Git processes use `windowsHide` to avoid opening consoles on Windows (#387).
- The README describes the v0.17.x test-optimization vision as future work, not an implemented or measured feature (#388).

The execution recovery and nested validation scratch changes were already delivered in v0.16.25 and v0.16.26. The older stale-evidence record did not retain a per-file snapshot diff, so its unique cause is still not established. These targeted Git boundaries do not claim to secure every Git operation.
