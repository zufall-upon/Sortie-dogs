# v0.16.31 — Reviewer transform failure isolation

Fix a critical V2 plugin-loading failure present in v0.16.30. A retained Reviewer correction registration can replay before OpenCode materializes the configured Reviewer role. The correction callback previously threw when the shipped permission block was absent, causing OpenCode to disable the entire plugin and remove Operator recovery tools.

Correction transforms now fail closed locally instead of throwing into the native registry. Native reads confirm that replay actually produced a usable alias before selection. Cold restoration defers an unavailable correction until the configured role is available, retaining its recovery identity without accepting work or resetting cumulative accounting. A previously selected alias is restored before disposal. The exact shipped-block matching and surrounding user deny/ask rules remain authoritative; no session permission rules are replaced.

Regression fixtures cover lazy replay, late role materialization, control-tool survival, recovery, restoration and single settlement. The non-model native-host driver in `test/fixtures/reviewer-transform-host.mjs` exercises actual OpenCode registry replay and real tool registration in a private host with fixture session bookkeeping. It does not establish recovery of an already-running user session.

Runtime marker: `0.16.31-reviewer-transform-recovery-v1`. Preserve the published v0.16.30 archive and earlier candidates unchanged. Installation, publication and the running shared host's actual recovery must be reported separately. Shared-host reload or restart is not performed by this change.
