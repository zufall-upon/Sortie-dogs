# v0.16.12 — Mission-native Fabric and conditional Scout diagnosis

## Changes

- Allow two independent Luna implementation units to execute concurrently in separate managed worktrees within the existing Mission lifecycle. Preserve per-unit Goal reservations and settlement, candidate integration, formal validation, independent Review, cancellation and recovery. Dirty bases, overlapping or uncertain dependencies, unavailable preparation and incompatible explicit model choices retain the serial path.
- Execute combined-candidate checks through ordinary native shell calls and host hooks. Preserve native `deny`/`ask` decisions, bind evidence to the exact actor/call/candidate/command/directory and never turn refusal or missing completion evidence into PASS. A host-bound one-time interrupted-check retry retains prior accounting and reevaluates native permissions.
- Preserve other Missions' owned dirty worktrees during reconciliation, allow explicit retry after settled sibling failures, and generate integration patches independently of `diff.noprefix`. Retain the V1 named factory's numeric-exit completion contract without accepting missing exits or explicit errors/cancellation.
- Reuse existing Scouts for conditional parallel failure diagnosis when independent unresolved questions can change the repair. Known causes and cheap local investigation use the normal correction path; diagnosis is optional and does not create retry or rescue prerequisites.
- Preserve the currently selected OAuth route when seeding isolated CLI fixtures. Shared authentication and model defaults remain unchanged.

Integrated source PRs: #338, #339, #340 and #341. The existing six valid Fabric review findings were resolved through targeted corrections and related regression tests; CI success was not treated as finding resolution. See `docs/mission-fabric-late-review-20261107.md`.

## Retained native evidence and limits

- A fixed pre-release package completed two actual `openai/gpt-6-luna-fast#max` Workers, separate worktrees, combined-candidate native checks, independent Review PASS and Mission acceptance. Operator/Coordinator/Reviewer used `openai/gpt-6.1-sol#xhigh`.
- One same-package two-file comparison observed parallel at 269.268 seconds / $0.37528512 and serial at 274.891 seconds / $0.29740900. Cache/provider/load conditions were uncontrolled; the small time difference and higher observed parallel cost do not establish general speed or cost superiority.
- A natural saved-failure request voluntarily selected two parallel Scouts and handed their findings to a Terra/max Worker. It completed in 327.139 seconds / $0.31729072, versus 258.146 seconds / $0.26070580 for a same-package Worker-only companion. Both passed formal validation and Review; Worker read counts were eight in both arms. One Scout file-not-found recovered. These single-fixture observations do not justify automatic routing thresholds or broader parallelism.
- Comparisons use retained development packages, not the final release archive. Reflection's behavioral benefit and Advisor's effect on parent decisions remain unproven. No automatic model router or three-to-five-lane expansion is introduced. No formal public benchmark score is claimed. Token-price estimates exclude parent development chat and browser consultation billing.

## Release verification

The release routine fixes the integrated main commit and one archive/SHA-256, then runs candidate preflight, the mandatory full suite and actual final-archive Worker/model startup before global installation, tagging, GitHub Release and a single npm publication of that same archive. Successful source-level native completion evidence is reused instead of repeating those model tasks. Final receipts are retained under `_testenv/releases/0.16.12/`.

Global application updates both npm-global installations and the package resolved by `~/.config/opencode/plugins/sortie-dogs/index.js`. Existing model overrides and unrelated configuration are preserved. Installed-file identity is recorded separately from a running host's loaded version; the shared OpenCode service is not automatically restarted.
