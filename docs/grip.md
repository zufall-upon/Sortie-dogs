# Grip: retain human direction at an existing decision

Grip is a small V2 active-Mission improvement to native `question`, not a new GUI, role, approval service or external AI connector. It must not increase routine implementation or test approvals.

## Initial scope

The Mission Operator or Coordinator uses one single-choice question with `header: "Grip"` for an already necessary user-only choice about purpose, UX, approach, safety policy or priorities. Input paths, missing facts, multi-select questions, native permissions, non-controller sessions and unmarked questions are unchanged. Classification is explicit: unmarked important questions can be missed; the host does not claim to infer intent or detect every drift.

The host adds the Mission's desired outcome, explicitly labelled AI synthesis, and a permanent final choice, `目的に戻って外部相談` (English: `Revisit goal with outside advice`). A continuation such as “refer to the Chat consultation” is not the vision. Normal labels, order and descriptions are preserved. Reprocessing the same native call does not duplicate the prefix or choice. The model supplies the relationship to the outcome, the current decision, why it matters now and concise option tradeoffs; target 200–300 Japanese characters in the initial view. Keep concrete targets, actions, exclusions and material cost/retention conditions in the decision or option descriptions; move detailed background/evidence to ordinary chat before the Form without adding another question. Full user text is retained without modification. The host does not silently rewrite or truncate the summary, decision or normal choices to meet a display quota.

During the existing understanding step, the Operator supplies `vision: {summary, source_refs, translated?}` in `start_mission`; the Coordinator supplies/refines it in the ordinary `plan_units` call if absent or stale. This is part of the existing controller turn, not another LLM request or approval. `summary` describes the desired state rather than the implementation method. References resolve to this Mission's `user:<request id>`, `requirement:R1`, `context:<public message id>` or `snapshot:<context sha256>`. The latter retains access to original messages and ordered attachments/bytes through the existing context, not a copy of their contents into the Form. Reference existence is checked, not semantic correctness or user confirmation. Requirements and Project Memory can inform synthesis but are never automatically concatenated or promoted from another scope.

If evidence is missing/conflicting, omit the field (or use `null` to withdraw an unsupported summary). A missing/stale vision displays “not established”, without inferring a goal from the first request line or blocking old Missions on a migration gate. The summary is bound to its Mission and current requests/requirements; changes require ordinary re-synthesis. It never changes grants, budgets, validation or acceptance. Supply privacy-safe text in the user's current language, mark translations with `translated: true`, and keep source text, sensitive paths, secrets and attachment bytes out of the display. Original requests and attachment provenance remain unchanged and accessible through existing authorized context paths, not automatically sent outside.

The V2 2.2.2 Form renderer normalizes even blank-line-separated descriptions into one paragraph. New Grip questions therefore use visible icons, text labels and the separator ` ┃ `, not whitespace-dependent layout:

`🎯【達成したい姿・AI整理】目指す状態。 ┃ 🔗【今回判断との関係・AI整理】この判断が何につながるか。 ┃ ❓【今回の判断】何を決める？ ┃ 💡【なぜ今】今決める理由。`

English uses `🎯[Desired outcome · AI synthesis] … ┃ 🔗[Relation to vision · AI interpretation] … ┃ ❓[Decision] … ┃ 💡[Why now] …`. Translated summaries additionally say `／翻訳` / `/ translated`. Text labels remain meaningful without emoji rendering or color. The model starts the question with `今回判断との関係：…` / `Relation to vision: …`; if unknown it says so, rather than inventing a connection. The host replaces line boundaries with visible separators and decorates explicit relation/decision/reason headings; it does not infer semantic sections inside arbitrary prose. Already saved native offers retain their original question/options and answer identity, including old excerpt-only offers and retries after summary updates; only new offers receive the new formatting. The display and source references are fixed with each new offer. AI synthesis is not a user quote, and references are not proof of agreement or authority. This change does not claim to control native font size, wrapping or paragraph rendering, and adds no GUI, CSS modification or hidden-Unicode line-break workaround.

## Consultation and resume

The question, exact native caller/call identity and pending direction live in the existing Mission JSON. The offer is saved before the form opens, so a failed answer save cannot silently resume work. Only native completed `metadata.answers` is interpreted; quoted model output is not a user answer. Missed after hooks recover from the same native session/call's retained completed result. Free-form feedback is retained and reported as received while the direction remains held; incorporate it into a fresh corresponding choice, never reinterpret a replay as another answer.

Admission rechecks the current pending decision and open form inside the serialized Mission write: neither concurrent initial questions nor competing revised questions can both open while only one hold is tracked. Complete/dismiss an open Grip form or recover its native terminal before opening another revision; cancellation remains available during an unresolved history outage. Reusing one native call identity for a different/revised form is explicitly rejected rather than substituting the old question. Native-history or recovery-storage outages retain the durable hold and expose `recovery.status: "unavailable"`; reads, status, consultation, context construction and cancellation are not disabled by that observation failure.

Choosing external consultation retains the hold. New Mission planning, implementation dispatch, direct-unit start, scope expansion, review/correction and acceptance are held at the V2 tool boundary. Controller edit/write/patch and shell calls are also held, except a small exact subset of existing read-only checks (`pwd`, `git status --short`, `git status --short --branch`). The general classifier accepts some output/helper flags, so it is not treated as a safety guarantee: variants such as `rg --pre`, `git diff --output` and `git show --ext-diff` do not pass this pause. Native read/search remain available without a new parser or user approval. Existing Worker sessions and their execution, cleanup, settlement, reads, status, consultation, release and cancellation remain reachable. This is a user-requested pause of the current Mission direction, not a new security sandbox or a replacement for native permissions; arbitrary external-tool side effects are not inferred. Background processes are not killed by Grip. Controller cleanup uses existing release/cancellation paths, rather than an exception that could implement a held proposal.

The internal consultation handoff separates original requests, saved observations, undecided proposals and constraints. It reports `external_delivery: "not-sent"`: nothing is automatically transmitted. Use only a user-authorized recipient and disclosure scope, or prepare a handoff for the user. Do not dump the internal packet as the initial question. Summarize outside advice briefly as misalignment, recommendation, reason and changed direction; advice never grants execution authority.

After consultation, the corresponding revised question uses the exact `resume_header` shown in `operator_status.grip` or retained context, for example `Grip:012345abcdef`. A fresh completed native answer selecting one listed normal option releases the hold. An unrelated question, old call replay, free text, dismissal, ordinary chat or an external AI answer cannot release it. Free-form steering remains available, but must be turned into the corresponding explicit revised choice before execution. Cancel the Mission normally when it should not continue. Requirements, spending, validation and review gates are never reset or waived.

## Verification boundaries

Local regression covers fixed-choice insertion, source retention, short example payload, non-applicable inputs, save failure, missed-hook recovery, reload, stale/unrelated answers, corresponding resume, cancellation and the real V2 adapter before/after/context hook transport. A separate zero-inference probe renders the augmented payload through the real V2 native Form UI; it is not evidence of model instruction adherence, full Mission completion or performance improvement. No release/global apply is implied.

For Code Mode, OpenCode v2.2.2's `packages/core/src/tool.ts` passes each inner tool through `beforeExecute` before its executor; `packages/core/src/codemode/tool.ts` preserves the outer session/call context. The V2 adapter regression exercises that callback shape, rejects inner shell/planning before execution and permits inner reads. This is a pinned-source contract plus adapter regression, not an execution of the Code Mode interpreter or a new sandbox claim.
