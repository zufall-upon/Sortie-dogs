# Grip: retain human direction at an existing decision

Grip is a small V2 active-Mission improvement to native `question`, not a new GUI, role, approval service or external AI connector. It must not increase routine implementation or test approvals.

## Initial scope

The Mission Operator or Coordinator uses one single-choice question with `header: "Grip"` for an already necessary user-only choice about purpose, UX, approach, safety policy or priorities. Input paths, missing facts, multi-select questions, native permissions, non-controller sessions and unmarked questions are unchanged. Classification is explicit: unmarked important questions can be missed; the host does not claim to infer intent or detect every drift.

The host adds a labelled excerpt of the retained original user request and a permanent final choice, `目的に戻って外部相談` (English: `Revisit goal with outside advice`). Normal labels, order and descriptions are preserved. Reprocessing the same native call does not duplicate the excerpt or choice. The model supplies only the current decision, why it matters now and concise option tradeoffs; target 200–300 Japanese characters in the initial view. Full user text is retained without modification. The host does not silently rewrite or truncate the decision or normal choices to meet a display quota.

The V2 2.2.2 Form render probe displays all three choices and native free input. That renderer normalizes even blank-line-separated descriptions into one paragraph; short explicit purpose/decision/reason labels remain important. This change does not claim to control native font size, layout or paragraph rendering.

## Consultation and resume

The question, exact native caller/call identity and pending direction live in the existing Mission JSON. The offer is saved before the form opens, so a failed answer save cannot silently resume work. Only native completed `metadata.answers` is interpreted; quoted model output is not a user answer. Missed after hooks recover from the same native session/call's retained completed result. Free-form feedback is retained and reported as received while the direction remains held; incorporate it into a fresh corresponding choice, never reinterpret a replay as another answer.

Admission rechecks the current pending decision inside the serialized Mission write: two concurrent initial questions cannot both open while only one hold is tracked. Reusing one native call identity for a different/revised form is explicitly rejected rather than substituting the old question. Native-history or recovery-storage outages retain the durable hold and expose `recovery.status: "unavailable"`; reads, status, consultation, context construction and cancellation are not disabled by that observation failure.

Choosing external consultation retains the hold. New Mission planning, implementation dispatch, direct-unit start, scope expansion, review/correction and acceptance are held at the V2 tool boundary. Controller edit/write/patch and shell calls are also held, except a small exact subset of existing read-only checks (`pwd`, `git status --short`, `git status --short --branch`). The general classifier accepts some output/helper flags, so it is not treated as a safety guarantee: variants such as `rg --pre`, `git diff --output` and `git show --ext-diff` do not pass this pause. Native read/search remain available without a new parser or user approval. Existing Worker sessions and their execution, cleanup, settlement, reads, status, consultation, release and cancellation remain reachable. This is a user-requested pause of the current Mission direction, not a new security sandbox or a replacement for native permissions; arbitrary external-tool side effects are not inferred. Background processes are not killed by Grip. Controller cleanup uses existing release/cancellation paths, rather than an exception that could implement a held proposal.

The internal consultation handoff separates original requests, saved observations, undecided proposals and constraints. It reports `external_delivery: "not-sent"`: nothing is automatically transmitted. Use only a user-authorized recipient and disclosure scope, or prepare a handoff for the user. Do not dump the internal packet as the initial question. Summarize outside advice briefly as misalignment, recommendation, reason and changed direction; advice never grants execution authority.

After consultation, the corresponding revised question uses the exact `resume_header` shown in `operator_status.grip` or retained context, for example `Grip:012345abcdef`. A fresh completed native answer selecting one listed normal option releases the hold. An unrelated question, old call replay, free text, dismissal, ordinary chat or an external AI answer cannot release it. Free-form steering remains available, but must be turned into the corresponding explicit revised choice before execution. Cancel the Mission normally when it should not continue. Requirements, spending, validation and review gates are never reset or waived.

## Verification boundaries

Local regression covers fixed-choice insertion, source retention, short example payload, non-applicable inputs, save failure, missed-hook recovery, reload, stale/unrelated answers, corresponding resume, cancellation and the real V2 adapter before/after/context hook transport. A separate zero-inference probe renders the augmented payload through the real V2 native Form UI; it is not evidence of model instruction adherence, full Mission completion or performance improvement. No release/global apply is implied.

For Code Mode, OpenCode v2.2.2's `packages/core/src/tool.ts` passes each inner tool through `beforeExecute` before its executor; `packages/core/src/codemode/tool.ts` preserves the outer session/call context. The V2 adapter regression exercises that callback shape, rejects inner shell/planning before execution and permits inner reads. This is a pinned-source contract plus adapter regression, not an execution of the Code Mode interpreter or a new sandbox claim.
