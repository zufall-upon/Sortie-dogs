# Reviewer corrections in the same context

## Purpose

Allow the Reviewer that discovered a defect to correct it in its existing native session, run the necessary declared validation and make the requested commit. Avoid copying findings through Operator into a new Worker that has to rediscover the same code and failure.

This follow-up starts from PR #148, commit `9a32238c89d71b0cc473abf6417d797ccd6a24a5`. It is a separate change; background Operator execution alone does not implement Reviewer-authored correction.

## Required behavior

- Keep the original request and acceptance conditions. Correction does not create a replacement user task or expand authorized outputs.
- Reuse the actual Reviewer's native session/context, not just its model or a copied summary in a fresh session.
- Reuse existing scoped write authorization, validation evidence, budget and lifecycle accounting. Review completion, `CORRECTION_READY` or unit success alone is not acceptance.
- Preserve the correction author in durable lineage so a restart cannot make that author appear independent.
- Initial independent Review detects both Major and Medium defects. The same native Reviewer corrects all known defects, runs the inherited formal checks and requested commit/clean boundary, then explicitly self-rechecks the original requirements, retained findings and relevant impact within that correction Task. A separate same-author read-only Task remains only as a legacy fallback.
- A different Reviewer is conditional: only a concrete reachable Major risk remaining after self-recheck, with a short affected-path and serious-consequence reason. Medium severity, hashes, public-api/public-logic tags, uncertainty, `EVIDENCE_GAPS` and missing prose alone do not trigger another Reviewer. Known unresolved Major or Medium defects cannot be accepted.
- Record author self-recheck honestly as `self-rechecked`, `independent=false`, never independent `PASS`. Root still compares the current validated candidate with the verbatim original request before the existing successful completion receipt.
- Keep foreground/background paths and explicit failure/cancellation recovery consistent with PR #148.
- Ordinary read-only Review and non-implementation Missions must not acquire a routine writer or an unnecessary corrective run.

## Verification and handoff

The implementation exposes `sortie_v010_repair_review` to Operator and Coordinator, including their shipped tool settings. After a completed independent Review reports findings, that operation prepares a correction unit and returns a Task whose native `sessionID` is the original Reviewer child. The caller dispatches that exact Task; it does not have to transcribe findings or create a fresh implementation Worker.

For OpenCode **2.0.18**, the adapter uses the supported `agent.transform` and `session.switchAgent` APIs to temporarily switch that same session into a dedicated correction profile. Its preceding context, model/variant and author identity remain unchanged; its native agent identifier changes during correction and returns to the Reviewer profile on terminal/cancellation paths. The implementation no longer depends on the nonexistent 2.0.18 `permission.rules` API. This is not a new Worker session or a global grant to all Reviewers.

Native correction dispatch selects `dog-reviewer-v010`, not the hidden correction alias. Pinned `SubagentTool` resolves and asserts that original target in the actual caller's agent/session last-match context before looking up and comparing the existing child. The adapter keeps/restores that child on the original agent for this comparison, then activates its scoped alias at prompt admission, before the child's tool snapshot. This preserves wildcard-deny followed by original-target allow/ask, native saved permissions and explicit denies, without modifying parent registry or session rules, and avoids native different-agent model replacement. The hidden alias is a child execution profile, not a dispatch-permission resource.

The correction inherits the original acceptance/proof/declaration, authorized write union, declared commands, Git boundary and cumulative budget. Native permission projection removes only the shipped Reviewer's read-only shell/edit role entries, retaining all other configured rules in their original order. It adds neither literal-command grants nor copied historical denies: wildcard deny followed by a specific allow/ask and a final explicit deny keep their native last-match meaning. Native saved permissions and session rules remain native-owned. Custom Reviewer configurations whose shipped block cannot be identified remain an explicit compatibility limitation, not silently overridden permission.

Execution permissions and formal proof are separate. The correction uses the existing implementation native policy for focused tests, formatters, generators and other legitimate diagnostics; these do not satisfy an undeclared formal check. The common write gate and mission prohibition check inspect existing extractors' known destinations, and retain Git boundaries and post-commit locking. Unknown program internals are not statically proved safe or confined to the output union; no new shell parser, allowlist, approval or claim of complete output discovery is added. Ordinary Reviewer sessions stay read-only. Current-admission native results must show every inherited formal check in order, with successful exits and fresh saved source/candidate bindings.

Exact composite declarations are matched first: `node required-test.mjs && node check.mjs` or a semicolon declaration retains one atomic native call binding and its whole exit, never inferred member successes. Other coalescing follows the ordered declaration and current occurrence, not a longest Set match: for `[A,B,C]`, where `C=A&&B`, a successful `A&&B&&A&&B` records `[A,B,C]`; `[C,A,B]` records that order instead. Execution records and native-history verification share this decomposition, preserving repeats, failed-chain behavior and call/member/occurrence bindings. The native ShellTool asserts its actual scanner resources (including semicolon members); the adapter no longer invents parsed resources or synthetic shell denies. Native rules apply to whatever resources the host actually asserts, not additionally inferred whole-call/member resources. Standalone partial composites may run as diagnostics but never certify the whole formal declaration.

A terminal failed correction can call `repair_review` again for a new correction generation in the original author's same native session. Exact prior terminal/ownership and released reservation/writer must reconcile, the inherited declaration/scope/checks/Git boundary stay fixed, and remaining cumulative budget applies. Failed evidence/spend/history remain historical, not current acceptance; each new admission charges only its own native requests and settles once. Ordinary Worker retry, Rescue or `plan_units` cannot replace that correction owner. No new approval or artificial retry/time limit is added.

Normally the correction prompt instructs fix → all inherited formal checks/requested commit-clean boundary → explicit self-recheck of original requirements, all retained findings and relevant impact in the SAME Task. After existing successful unit settlement, the host adopts the actual successful native terminal after the exact admitted correction prompt, using current `missionReviewSource` and fresh saved check bindings. This eliminates the mandatory extra read-only model round, not an independent review: author self-recheck remains non-independent. The tradeoff is that no separate “look again” prompt is mandatory; explicit comparison and formal quality checks remain required.

Legacy `CORRECTION_READY` without a valid inline report still makes `review_mission` return `status: self-recheck-required`, resuming the same author read-only with no writer. The host supplies complete original requests, baseline/candidate/diff, native check observations and actual tools; relevant direct search may widen normally. Missing prose, optional traces and routine root rereads are not new gates.

The native self-recheck terminal format is:

```text
SELF_RECHECKED
self_recheck: {"candidate":"current-validated","unresolved_findings":[],"residual_major":null}
<actual comparison of original requirements, findings, correction and relevant impact>
```

`current-validated` is a host-binding marker, never an edited hash copied by the model. The host stamps actual current source after the exact prompt's successful terminal and formal checks. The legacy read-only fallback also accepts its supplied current fingerprint. Put known unresolved Major/Medium defects in `unresolved_findings`; these require correction by the original author. A concrete residual Major risk uses `residual_major: {"reachable_path":"<reachable input/path>","consequence":"<serious consequence>"}`. Only that risk triggers a different Reviewer, supplied with correction, retained findings, author self-recheck and relevant impact. New second-side findings return to the original correction owner in a new finding generation, not a fresh Worker or the already-settled correction Task.

Additional/changed evidence excerpts never trigger a second Reviewer on their own. `candidateFingerprint` excludes optional excerpt selection; `fingerprint` still pins the accepted evidence and its full bytes. An accepted unchanged candidate remains recorded without another author Task for presentation-only changes, retaining its old evidence pin rather than adopting new unreviewed evidence. Changed pinned evidence or source that needs a fresh disposition resumes the same author read-only. The old report cannot accept refreshed generations or authorize a different Reviewer: residual Major authority must match current run/source/author and completed native report. Omitted evidence retains the pin; fresh checks and exact-prompt terminal guards remain.

Observer fields: `units[].reviewerCorrection.promptID` persists the actual correction admission's message ID; `admittedAt`, correction `callID` and author remain unchanged. Inline disposition uses `review.task=null`, `review.mode="self-recheck"`, `review.verdict="self-rechecked"`, `review.callID` equal to the correction call, `review.promptID` equal to that correction admission and matching `review.selfRecheck` / `corrections[].selfRecheck`. The report retains `runID`, host-stamped `source`, optional `candidateSource`, `author`, `callID`, `promptID`, actual terminal `messageID`, `nativeOutcome:"completed"`, terminal `result`, `unresolvedFindings` and optional `residualMajor`. `review.candidateSource` records the presentation-independent identity. Observer must use the correction admission for inline proof, not require a second admission or infer success from terminal text alone.

Acceptance still requires native unit success, actual successful terminal after the exact prompt with no later unrelated user prompt, same author/owner/current run, current source, fresh saved formal check bindings, requested Git boundary, no unresolved Major/Medium and no residual Major. Plain author `PASS`, missing/nonterminal/stale self-recheck and `CORRECTION_READY` alone are not acceptance. Summary/packet/report show `independent=false`, `passed=false`, `accepted=true` and verdict `self-rechecked` honestly.

While an owned background child runs, short launch acknowledgement and root idle are nonterminal: no interruption label or Mission receipt. The real native terminal/wakeup settles existing ownership and spend once. A reused child's old idle/report does not settle a newer correction or self-recheck prompt.
