# Mission debrief

The return card is generated by the plugin from typed host observations. It does not call a model or
ask an agent to calculate numbers or award badges. The existing first-line terminal checkpoint and
Japanese change, verification, and next-action paragraphs remain intact.

## Sources and boundaries

- Elapsed time and acceptance completion come from the goal receipt and goal ledger.
- Token totals retain the host's existing input/output/reasoning/cache accounting. The model mix is
  a **token share**, not a cost share. Provider and model identity come from each usage record; role
  names are not treated as model tiers. Unrecognized models retain their actual model identifier.
- Pack counts are unique non-root child sessions with observed execution in the receipt window.
  Resuming the same child does not add another dog. A child using multiple models is counted once as
  `混成`; its tokens remain allocated to their individual models. Coordinator tokens are included in
  model mix and total usage, but the coordinator is not included in pack counts.
- Coverage is evaluated per metric. Missing elapsed-time metadata does not erase known model usage
  or identified child sessions. Missing values are not replaced with invented zeros. The snapshot
  is pre-terminal: final-answer generation is not included.
- Dollar values are explicitly **host estimates**, not subscription billing or attributable actual
  spend. No subscription plan is inferred from a provider name.
- Target validation uses native integer shell exit metadata for exact commands declared in the
  acceptance contract, including native evidence referenced by the terminal receipt. It is not a
  test-case count, and acceptance success alone does not imply review success. Controller-confirmed
  reviews and completed serial reviewer Task reports are distinguished; the latter are labeled
  `reviewer報告`. Coordinator/worker claims do not become a review verdict. Skipped review is waived.
- Detailed observations are extracted during the existing bounded host-history pass, then discarded.
  No raw conversation, patch, command, or tool output is included in the debrief snapshot. Commands
  used for matching are retained only as hashes. The final ledger read is reused for attempt coverage.

## Traits

- **連携作戦**: distinct worker execution intervals positively overlap. Mere dispatch count is
  insufficient. This describes activity, not successful delivery or saved time.
- **修正から復帰**: a declared validator fails, a host-confirmed patch changes content, then that
  exact validator passes in the same child session; the final goal is complete and the covered
  target validators pass. Cross-child failures and successes are not combined.
- **一発完遂**: a complete terminal-matched goal ledger and complete host observations prove
  successful settled units, no retries/resumes, no failed checks or process denials, no replan,
  and successful declared validation. Missing history is not a clean run.

Unprovable traits are omitted. Unsupported review or mutation evidence remains unconfirmed. There
are no quality scores, XP, hypothetical worker-hours saved, or unmeasured Bare comparisons.

## Compatibility and display

`SortieResult.schema_version` remains `0.1`: `debrief` is additive and optional. Old snapshots render
with unavailable pack/model/review fields. Machine states stay `DONE`, `INTERRUPTED`, `BLOCKED`, and
`NEED_DECISION`; the visible text distinguishes completion, interrupted return, external waiting,
and waiting for a user decision. Internal proof remains in its existing store.

Rendering is deterministic. Existing card lines, including model-authored or legacy values, are
replaced with the observed snapshot. Repeated insertion produces one card. Rendering failure falls
back to a concise status-preserving message; it does not change the accepted outcome.

Model shares use ten-cell text bars alongside exact one-decimal percentages. Bars are rounded visual
aids, not additional measurements. At most four model rows plus an `その他` remainder are shown.

## Career: retained project records

`PACK RECORD` summarizes existing goal ledgers in the project Git metadata and the legacy project
ledger directory. At most 64 files, including the current ledger, are read per terminal snapshot.
The card displays the included file count, any partial coverage, and the earliest retained goal date.
It is never described as lifetime history. No additional database, cloud service, per-tool writes,
model invocation, XP, level, sound, or dashboard is introduced.

The existing ledger gains one bounded `goal.reported` telemetry event tied to the exact terminal
receipt fingerprint. It stores the token accounting definition, measured tokens/model totals,
first-pass eligibility, and three evidence-based traits. It stores no conversation or tool output.
Repeated reporting of the same receipt is idempotent under the ledger's existing lock. Recording
failure is a nonfatal warning and does not alter goal state or acceptance. Old ledgers without this
event still contribute their known mission counts; missing measurements remain outside the measured
cohort. A resumed goal's latest receipt/report replaces its previous contribution, including when its
revision number stays the same. Current active goals are separate from terminal mission counts.

Career includes completed, interrupted, externally blocked, and decision-waiting missions; eligible
first-pass completions; measured validation recoveries; model/token usage; and covered worker and
summed goal time. Summed goal duration includes waiting and can overlap other goals in calendar time.
Neither this sum nor worker time proves execution compression or saved time. Currency totals,
compression, scope-violation counts, and comparative savings are omitted until compatible evidence
exists. No estimated prices from different model or price definitions are silently combined.

The separate **worker-span overlap ratio** is available when host timestamps cover the child
sessions: sum of each child's union of assistant-message intervals divided by the union across all
children. Tool/provider waits inside those intervals remain included. It is not CPU utilization,
speedup, or saved time. A failed/cancelled worker with known intervals still contributes; incomplete
timing makes the measurement unavailable. The compatible `worker-span-union/v1` measurements are
aggregated as `sum(worker_ms) / sum(wall_ms)`, never as the mean of individual ratios. This clock is
separate from ledger worker time and the summed goal-duration clock above.

Presentation records are checked on write but ignored by execution replay. An unsupported future
telemetry definition is omitted from Career measurement cohorts without blocking the original goal.

The additional team titles are deterministic and have no points or levels:

- `任務完遂の隊`: at least one retained successfully completed goal.
- `連携の隊`: at least one retained report proving worker overlap.
- `復帰の隊`: at least one retained completed goal with proven recovery.
- `一発完遂の隊`: at least one retained eligible first-pass completion.

Retention or deletion of source ledgers changes the next aggregate; there is no hidden lifetime
counter resurrecting removed history. Career has no independent reset that deletes execution state.


This writes `_testenv/mission-debrief/preview.md` using the actual renderer for all four terminal
states. All values are **synthetic fixtures**, not performance measurements or a benchmark win.
Open the Markdown preview in the intended host to check typography and emoji support. The generated
file and any screenshots remain test artifacts; Desktop rendering is a separate visual check.
## Terminal display compatibility

The first terminal status determines the report, not its decorative icon. For example,
`⛔ **INTERRUPTED**` and `⚠️ **INTERRUPTED**` both denote interruption. A different icon must not
suppress the mission debrief or leave the obsolete collapsible Evidence block visible.

Internal Evidence details are removed from terminal presentation; the host-generated mission
debrief remains the user-facing report. A paused or interrupted goal is reported as such rather
than converted to success merely to display the report.

The debrief and PACK RECORD are inside one initially closed `<details>` area. Its summary contains
the mission outcome; important values use bold emphasis and colored status markers (green success,
yellow interruption/user decision, red external blocker). These markers remain legible without
renderer-specific CSS. Goal elapsed time is labeled as including waits and uses hours for long goals.

Completed-message membership follows the same time window as token aggregation. Execution spans
crossing the beginning of the goal are clipped instead of invalidating pack/mix/validation together.
Unknown metrics state the missing data category. Unrelated tool metadata gaps cannot erase a native
canonical PASS or an observed serial review result; genuine incomplete first-pass history remains
ineligible for a first-pass badge.

Ordinary explanations are not terminal reports. The coordinator should answer explanatory questions
with the requested context instead of forcing them into a status/Validation/Next template. Renderer
cleanup removes internal Evidence blocks and replaces its own cards; it preserves user-facing prose,
explanatory disclosure sections, and code examples. Legacy card cleanup is restricted to identified
card blocks rather than deleting every paragraph with a familiar heading.
